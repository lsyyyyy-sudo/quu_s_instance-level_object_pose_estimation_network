### 结论

**① 在约 200 epoch 处就收敛了，`max_epochs: 500` 过量。**

```
train/loss_epoch   150 → 1.22         val/corner_err_px   ~31 → 16.6
val/pck@0.05        —  → 0.804        val/pck@0.1         —  → 0.863
val/pck@0.15        —  → 0.895
```

前 15 个 epoch 就从 30 降到 23，之后 240 个 epoch 只再降到 16.6，
**最后 25 个 epoch 完全没动**（16.2~17.1 之间抖）。
→ **下次把 `max_epochs` 设成 150~200。**

**② 只看 2D 角点口径，不看 6D 位姿。**（本项目交付物是 8 个 2D 角点，也不需要内参）

```
像素误差 (256 裁剪系)   mean 16.04 | median 3.34 | p90 39.85 | p95 101.34 | max 235.0
归一化误差 (÷对角线)    mean 0.061 | median 0.013 | p90 0.149 | p95  0.376
PCK@0.02 62.6%  @0.05 80.8%  @0.10 87.2%  @0.15 90.1%  @0.20 91.7%
失败率  >0.05 对角线 19.3%   >0.10 对角线 12.8%   >0.20 对角线 8.3%
框 IoU  mean 0.907 | median 0.961 | 仅 1.2% 样本 IoU < 0.5
```

**中位数 3.34 px vs 均值 16.04 px，差 4.8 倍 → 重尾分布。**

**87% 的角点很准，13% 完全崩掉**，且崩的不是"略偏"，是**飞到画面另一端**
（p95 = 101 px、max = 235 px）。**是质变不是量变。**

**③ 失败模式 = 遮挡处的 amodal 外推。** 见 `data/results/stage3_train_v1/eval_corners.png`：

- 好样本（err 2.4~4.8 px）：8 个角点全中
- 坏样本（err 54~145 px）：**多数角点仍对，一两个飞到画面外**；共同点是**物体被部分遮挡**

**因果链**：被遮挡、裁剪图里不可见的角点必须**外推**，而 v1 训练集 95% 完全可见，
**模型从没学过外推** → 遇到遮挡就瞎猜。

→ **这是 v2 要验证的核心假设：带料箱 + 可见性过滤的 v2 应把失败率（12.8%）降下来。
评估看失败率，不看均值。**

**④ 瓶颈不在角点提取方式。**（同一 checkpoint 对照）

| 方式 | `corner_err_px` | `pck@0.05` |
|---|---|---|
| `soft_argmax` | **15.82** | **0.8185** |
| `topk(20)`（默认） | 15.99 | 0.8095 |
| `argmax` | 17.29 | 0.8060 |

差距只有 0.2 px，**说明问题是模型/数据，不是后处理**。
（`configs/model/heatmap.yaml` 里那句「等有真实训练模型后应用验证集实测再定」
现在有答案了：`soft_argmax` 略优，但不必为此改动。）

### ⚠️ 走过的弯路：第一版评测用错了口径

第一次评测时打开了 `solve_pose`，报出：

```
add = 157.84 mm   （物体直径只有 81 mm，BOP 判据是 ADD < 8.1 mm）
rot_err_deg = 28.06°     trans_err_mm = 156.55 mm     acc_5cm5deg = 0.540
```

据此得出「6D 位姿完全失败」的结论 —— **那是拿错标准打分**。
位姿对 70 mm 小物体的 2D 误差极其敏感，会把「角点其实还行」读成「完全失败」。
**交付物是 2D 角点，就该用 2D 角点的指标。**
